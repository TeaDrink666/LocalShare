# LocalShare 任务中心

## 使用方式

- 主导航按「首页、任务、发送、同步、设置」排列。发送、接收、照片／视频同步以及实际网页下载均显示为任务。
- 首页可确认接收请求、查看当前任务，网页入口区分发送和接收。旧接收历史从任务页「接收文件」入口访问，已完成文件可从任务详情打开。
- 列表显示进度、传输字节、已用时间、速度和预计剩余时间。速度以最近约 10 秒估算，剩余时间在获得有效速度后显示；等待、暂停和校验阶段不显示剩余时间。
- 点击任务查看文件状态、错误和保存目录。返回或切换页面只关闭视图，任务继续执行。
- 「取消任务」单独操作。原生发送可以暂停、继续或重试；接收端的暂停／中断记录等待发送设备重新连接继续。
- 网页分享页面返回后保留服务；「停止网页分享／接收」才终止相应网页传输。网页下载的完成表示服务器已发送响应，浏览器最终落盘由浏览器负责。

## 调度

默认最多同时执行 2 个传输任务，在设置中可改为 1–8 个。其余任务排队。降低上限时，已有任务继续，新增任务按新上限调度。每个原生发送任务同时上传一个文件，避免任务数和单任务连接数相乘。

照片／视频同步额外限制为 1 个；同一批次的重试等待旧执行流程结束。接收确认和发送准备阶段不占用传输名额，新版双方会协商开始传输，接收端没有名额时发送端释放本地名额并等待重试。

## 文件保存

普通接收在默认接收目录下创建独立任务目录，例如：

```text
Downloads/
  接收_20261005120000_a1b2c3d4/
    project/lib/main.dart
  接收_20261005120001_e5f6a7b8/
    project/lib/main.dart
```

原文件名与相对目录层级保持不变。目标系统无法表示的名字、同一任务内的重复路径、大小写冲突或文件与目录冲突会直接报错，要求调整选择或拆分任务。完成文件采用不覆盖已有文件的方式提交；Android 系统目录提供者擅自改名时，任务报错并移除刚创建的文件。

照片／视频同步继续使用既有媒体备份目录和图片／视频分类方式，不创建普通任务子目录。

## 续传与兼容性

原生 LocalShare 双方升级后，准备响应通过 `localshareResume` 和 `localshareAdmission` 扩展协商。扩展路由独立于 LocalSend 原协议：

- `POST /api/localshare/v1/transfer/start`：协商执行名额。
- `GET /api/localshare/v1/transfer/status`：查询接收端持久化偏移和最终提交状态。
- `POST /api/localshare/v1/transfer/chunk`：上传最多 8 MiB 的数据块。

发送端先计算整个源文件 SHA-256；接收端验证每块 SHA-256，写入并刷新数据、保存偏移后才确认。所有字节齐备后验证全文件，发布完成文件并持久化最终状态。响应丢失时，再次连接可识别已经完成的文件。应用被终止后，任务记录显示中断，用户可重新连接发送设备并继续；源文件改变时要求创建新任务。

旧客户端继续使用标准整文件上传。Android `content://` 系统目录使用整文件方式，当前不支持字节续传；网页版上传使用原有协议。浏览器单文件下载保留 HTTP Range 支持，ZIP 不支持续传。

普通文件的临时续传数据保存在应用支持目录的 `localshare-transfer-data` 中；稳定键由发送设备、任务和文件 ID 共同生成。暂停和中断保留这些数据，取消清除未完成数据；清除任务记录清除其续传元数据，不删除已经保存的最终文件。

## 记录与后台范围

任务记录保存到本地。可手动清除已完成、已取消记录，也可单独清除终态记录；设置中的保留时间为 7／30／90 天或永久，默认 30 天。启动和修改保留时间时清理过期的已完成、已取消记录；失败、暂停和中断记录保留，便于恢复。

媒体同步的接收确认与手机确认记录更新属于任务流程，不依赖备份页面仍然存在。短暂的本地确认写入继续保护返回操作，原生传输期间允许离开页面。

本阶段保证应用运行期间任务不依赖页面。Android 息屏、系统后台限制、进程保活和重启后的自动调度属于下一阶段。现有接收前台服务在最后一个对应传输结束后释放；这不等于已经验证手机息屏下可靠运行。
